2025.07 – 운영 중

충청남도교육청 과학교육원 장기현장실습, 혼자 만들고 운영

실습생 3명과 과학해설사 7명, 모두 10명이 프로그램마다 흩어진 4~5개 예약 페이지를 돌며 수업을 확인했다. 예약은 오전 9시와 오후 1시에 열리고, 마감 직전까지 다시 봐야 했다. 나도 그 10명 중 한 명이었다.

그래서 예약 현황을 크롤링해 한 화면에 모으는 앱을 만들었다. 처음엔 내 불편만 풀려고 조회 기능만 넣었다. 매달 파일로 받던 근무표도 세 구역 자동 순환 배정과 근무 변경 기능으로 바꿨다.

  1. 2025.07혼자 쓰려고 조회 기능만 만들었다.
  2. 같이 쓰자는 실습생 2명이 붙어 3명, 이를 본 해설사 선생님들이 합류해 10명이 됐다.
  3. 2025.10전시관 공사로 예약 페이지 구조가 바뀐다는 소식을 한 달 전에 듣고 대비했다. 바뀐 당일엔 데이터를 받아오는 코드만 고쳤다.
  4. 2026.07실습이 끝난 뒤에도 유지보수를 이어가며 자연어로 묻는 AI 예약 비서를 붙였다.
  5. 2026.09지금도 10명이 쓰고 있다.
구성과 1년 뒤 고친 것 보기접기

구성

  • React Native(Expo) 앱과 Node.js(Express) 서버. 서버가 운영 시간(09:00~18:59)에 10분마다 크롤링해 SQLite에 캐시한다.
  • fly.io에 GitHub Actions로 자동 배포한다.

1년 뒤 내 코드를 다시 리뷰하고 고친 것

  • CORS 전체 허용을 허용 목록으로 바꿨다.
  • 챗봇 API에 분당 10회 제한을 걸고, 에러 응답에서 내부 메시지를 뺐다.
  • 크론과 기동 시 크롤링이 겹치지 않게 동시 실행 락을 걸고, 크롤링이 실패하면 webhook으로 알린다.
  • Firestore에 최소 권한 규칙을 배포하고, 근무표 화면의 로컬 캐시와 서버 동기화 경합을 고쳤다.

남은 한계

  • SQLite에 볼륨이 없어 서버가 재시작되면 캐시가 비워진다. 기동 시 다시 크롤링해 복구되지만 전날 기록은 잃는다. README에 적어 두었다.

같은 실습에서 한 일: 소스 없는 전시물 되살리기

  • 유아과학관 미각체험 전시물이 자주 멈췄다. 10년 전 Flash로 만들어졌고 원본 소스가 없었다.
  • SWF를 디컴파일해 하드웨어 통신부의 메모리 누수를 찾아 고쳤고, 이후 Electron 키오스크로 다시 만들었다.
  • 신호와 영상의 연결을 설정 파일로 빼서 코드를 고치지 않고도 바꿀 수 있게 했다.

학사 규정 상담 AI

2026.08

SKALA 2인 팀, 4일. 모델 설정부터 문서 인제스트, 검색, 답변, 메모리까지 AI 쪽을 맡았다.

학사 규정 PDF를 근거로 답하는 상담 AI다. 첫 골든셋 평가에서 20문항 통과율이 75%로 기준에 못 미쳤다. 기준은 낮추지 않았다. 틀린 답을 하나씩 열어 봤다.

질문을 자세히 쓰면 처음부터 맞게 답했다. 하지만 실제 학생은 짧게 묻는다. 그래서 프롬프트가 아니라 검색을 고쳤다. 고친 뒤에도 기대 키워드는 나오지 않았지만, 통과시키려고 문항을 다시 다듬지는 않았다.

최종 골든셋 20문항 통과, 자동 테스트 135건, 레드팀 시나리오 10종을 통과했다.

다른 결함 두 개와 협업 방식 보기접기

위조 문서가 공식 출처로 표시되던 것

  • 입력 검사는 사용자가 친 질문만 봤고, 검색된 문서 본문은 아무도 보지 않았다.
  • 규정 말투를 흉내 낸 위조 문서에 지시문을 심어 보니, 답변은 지켜냈지만 그 문서가 출처 목록에 공식 문서처럼 올라왔다.
  • 인제스트할 때 문서 전체를 검사하게 바꿨다. 청크 단위로 검사하면 지시문이 청크 경계에서 잘려 놓쳤다.

정답인데 출처가 사라지던 것

  • "근거가 없다"는 표준 문구가 답변 어디에든 있으면 출처를 지우는 규칙이, 정답 뒤에 붙은 단서 문장에도 걸렸다.
  • 근거 없음 문항 3개를 3번씩 호출해 보니 표준 문구가 나온 7건 모두 첫 문장이었다. 첫 문장일 때만 지우도록 좁혔다.

협업

  • 역할표로 파일 소유를 나누고, 서로의 코드를 2차 담당자로 리뷰했다. PR 16건, 리뷰 18건.
  • 스트리밍이 끊기면 대화 메모리가 저장되지 않던 문제를 고치다 만든 경합을 동료 리뷰가 잡아 줬다.

EyeWaveVR

2024.09 – 2025.05

졸업설계, 5인 팀 팀장

VR에서 시선과 뇌파를 함께 수집해 ADHD 아동의 집중력과 충동 억제를 훈련하고 점수로 보여주는 시스템이다. 팀장을 맡으면서 Unity 훈련 콘텐츠 개발에도 참여했다.

처음 설계는 VR 결과를 Unity 서버에만 저장하는 구조였다. 그 데이터를 봐야 할 의료진은 이 형태로 확인하기 어렵겠다고 판단했다. 그래서 의료진용 웹 대시보드와 보호자용 앱을 추가하기로 했고, 두 프런트엔드는 내가 맡아 만들었다.

최종보고서 자기평가 8개 항목 중 3개에는 스스로 "충족하지 못함"을 적었다. 의료진과 보호자의 요구를 인터뷰로 확인하지 못했고, 동의 절차와 윤리 검토가 없었고, 측정 정확도 문제가 남았기 때문이다.

환아가 아닌 팀원 계정의 테스트 데이터로 찍은 화면이다.

대시보드 상세와 VR 콘텐츠 보기접기

보호자용 앱 (React Native, Expo)

  • 문자 인증으로 가입하고 자녀 계정과 연결해 세션별 점수와 변화를 본다.
  • 인증이 만료되면 자동으로 로그아웃되게 하고, GitHub Actions로 브랜치별 앱 빌드를 나눴다.

점수
