의료진이 볼 화면을 더 만들었고, 확인받지 못한 것은 자기평가에 '만족하지 못함'으로 적었다

사례
EyeWaveVR, 'VR 기반 아이트래킹과 EEG를 활용한 ADHD 환아 증상 개선 컨텐츠'
내 역할
팀장, 의료진 웹 대시보드와 보호자 앱 프런트엔드, Unity 훈련 콘텐츠 개발 참여, 두 학기 최종 발표
팀
5인
기간
2025.03 – 2025.06, 졸업설계(2025년 1학기). 팀장으로는 공학설계(2024년 2학기)부터
도구
React, React Native(Expo), Unity, 시선 추적 VR 헤드셋, 뇌파 측정기

문제

ADHD 치료는 약물에 기대는 비중이 크고, 기존 디지털 치료제는 생체 신호를 쓰지 않거나 실시간 피드백이 부족했다.

내가 한 일

VR에서 시선과 뇌파를 함께 수집해 아이의 집중력과 충동 억제를 훈련하고 점수로 보여 주는 시스템을 팀장으로 이끌었다. 의료진 웹과 보호자 앱은 내가 맡아 만들었다.

결과

저장소 4개(VR·백엔드·웹·앱)로 나눠 완성했다(팀). 최종보고서 자기평가 8개 항목 중 3개에는 스스로 X(만족하지 못함)를 적었다.

가치 관점: 화면을 누가 보나

사용자는 셋이었다. 훈련하는 아이, 데이터를 봐야 할 의료진, 결과를 받아 보는 보호자다. 처음 설계는 VR 결과를 Unity 서버에만 저장하는 구조였다. 나는 그 데이터를 봐야 할 의료진이 이 형태로는 확인하기 어렵겠다고 보고 웹 대시보드와 보호자 앱을 제안했고, 팀 논의를 거쳐 추가하기로 했다.

원시 신호가 그대로는 읽히지 않아 구간 평활과 확대를 넣었고, 전문가가 따로 분석할 수 있게 CSV로 내려받게 했다. 이 판단은 의료진에게 확인받지 못했다.

구현 관점: 결정 기록

저장소를 둘에서 넷으로

웹과 앱을 더하면서 저장소가 VR과 백엔드 2개에서 웹과 앱을 합친 4개로 늘었다. 두 프런트엔드는 내가 맡아 백엔드 담당 팀원과 함께 완성했다.

점수는 어떻게 만들었나

팀은 동공 크기와 눈 깜빡임으로 집중력을, 뇌파의 세타/베타 비율로 충동 억제를 계산했다. 두 점수는 각각 27점 만점으로 맞추고, 상태 구분은 임상 ADHD 평가 척도를 참고했다. 전문가 검토를 받지 못해 임상적 진단이 아니라는 점을 README에 밝혀 두었다.

보호자 앱에서 신경 쓴 것

인증이 만료되면 자동으로 로그아웃되게 했다. GitHub Actions에서 브랜치에 따라 앱 빌드 설정을 나누고, 겹친 빌드는 취소되게 했다.

장비가 서로 부딪혔다

시선 추적과 뇌파 장비의 SDK가 충돌했고, 팀은 반복 테스트와 캘리브레이션, 데이터 필터링으로 맞췄다.

공학설계에서 졸업설계로

같은 팀은 앞선 공학설계(2024년 2학기)에서 'VR 상담 서비스' 아이디어로 학부 우수작품상을 받았다. 졸업설계에서는 당시 LLM 수준과 직접 구현할 부담 때문에 주제를 바꿨다. 연구실의 시선 추적·뇌파 장비로 풀 수 있는 문제를 찾다 ADHD를 골랐다.

결과와 한계

저장소 4개로 나눠 완성했다(팀). 화면은 모두 테스트 데이터다. 의료진 인터뷰와 사용자 테스트, 동의 절차와 윤리 검토는 하지 못했다.

배운 것

4학년이 되기 전까지 CS를 주입식으로 배우다가, 진짜 서비스를 만드는 재미를 처음 알았다. 프런트엔드로 협업한 첫 경험이기도 하다. 지금이라면 원래 공학설계 주제도 구현할 수 있을 것 같아 아쉽다.

근거

  • 공개 저장소 4개: VR 콘텐츠, 백엔드, 의료진 웹, 보호자 앱
  • 최종보고서(비공개)

이 사례는 소개 첫 문단의 출발점이다. 사용자를 생각해 범위를 넓혔지만, 그 판단을 사용자에게 확인받지는 못했다. 간호 인계 설계에서는 첫날부터 현직 간호사에게 확인받았다.
