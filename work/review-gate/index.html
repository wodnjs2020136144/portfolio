문제

과목마다 교안이 오는 시점이 달라 실습 가이드를 매번 급하게 만들었고, 같은 프롬프트를 과목마다 손으로 고쳤다. 결과물을 만든 모델이 스스로 검증하면 자기 흐름대로 통과시킬 수 있었다.

내가 한 일

프롬프트를 변수와 결정표가 있는 템플릿으로 묶고, 위험도가 높은 작업은 다른 계열 모델의 교차 리뷰를 거쳐야 Python 게이트를 통과하게 했다.

결과

리뷰로 찾은 구멍을 회귀 테스트로 옮겼다(9월 14일 52개, 9월 28일 65개). 그 테스트가 게이트 코드 자체의 결함 6건을 잡았다(9월 14일 기준).

자료 1정리하는 모델과 검토하는 모델을 나누고, 통과는 게이트가 판정한다

  1. 교안과목마다
  2. 정리Claude
  3. 교차 리뷰다른 계열 모델
  4. 게이트gate.py, exit code
  5. 통과 또는 막힘기록이 남는다

리뷰가 찾은 구멍은 test_gate.py의 회귀 테스트가 되어 게이트를 다시 시험한다.

가치 관점: 쓰는 사람도 결정하는 사람도 나다

그래서 AI가 "검토했다"고 말하는 것으로 끝내지 않고, 기록과 게이트로 확인하게 했다. 기록하는 습관은 청년인턴 때 시작됐다. 들은 설명을 적어 두지 않아 대부분 잃었다.

구현 관점: 결정 기록

75쪽 교안을 2쪽만 정리해도 통과했다

첫 게이트의 구멍을 교차 리뷰가 찾았다. 쪽마다 넣고 뺀 이유를 적게 하고, 그 기록을 교안 전체 쪽수와 대조하는 검사를 넣었다.

리뷰 지적은 테스트로 남겼다

리뷰가 찾은 구멍을 회귀 테스트로 옮겼다. 4차 리뷰 뒤 40개에서 52개로 늘었고(9월 14일), 9월 28일에는 65개였다. 그 테스트가 게이트 코드 자체의 결함 6건을 잡았다(9월 14일 기준). 다른 작업의 리뷰 파일로도 통과되는 것처럼, 작업 ID와 위험 플래그가 게이트 입력에 묶이지 않은 빈틈 4건도 리뷰로 찾았다.

교차 리뷰는 A 등급 4과목에만 붙였다

산출물의 밀도는 모든 과목에서 같게 두고, 검증 강도만 등급으로 나눴다. 모든 과목에 리뷰를 붙이는 안은 버렸다.

결과와 한계

게이트는 쪽 커버리지, 리뷰가 있는지, 지적의 형식을 검사할 뿐 내용이 맞는지는 판정하지 않는다. 시범 운영은 목표 6건 중 4건을 했다.

근거

  • 공개 저장소는 없다. 게이트 코드와 테스트, 워크플로우 문서, 리뷰 기록은 개인 작업 폴더에 있다.
